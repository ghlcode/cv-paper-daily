## 它是怎么工作的

1. `.github/workflows/daily.yml` 每天定时触发（也可在 Actions 页面手动 `Run workflow`）。
2. `scripts/fetch_papers.py` 调用 arXiv Atom API，按投稿时间倒序**分页**取 `cat:cs.CV` 的最新条目（默认最多 800 条，每页 500，请求间按 arXiv 要求间隔 3 秒）。
3. 用 `papers.json` 里的 `seen_ids` 记住所有抓到过的 arXiv ID（去掉版本号），与索引合并；已收录论文若摘要/作者有修订会同步更新。
4. 生成 `data/YYYY-MM-DD.md` 当日清单，并刷新本文的「最新论文」表格与归档列表。
5. 若内容有变化，工作流自动 commit 并 push 回仓库，因此仓库历史本身就是一份完整的每日快照。

去重规则：**只有「从未见过」且投稿日期落在最近 7 个 UTC 自然日内的论文才会被收录**，历史论文即便仍出现在抓取结果里也不会被误判为新增；反过来，某天因故障漏掉的稿件，只要还在窗口内、还出现在最新一批结果里，下次运行就会补录。窗口按自然日计算（不是滚动时间戳），边界不会随运行时刻漂移。**首次运行**会把窗口内的历史论文写进索引，但只有最新一个投稿日的论文进入当天归档，避免第一天就产出一份超长清单（也避免周末首跑时归档为空）。`papers.json` 最多保留 5000 条论文与 8000 个已见 ID 以控制仓库体积。

## 本地运行

需要 Python 3.9+，无需安装任何依赖：

```bash
# 正式跑一次（会写 data/ 和 README.md）
python scripts/fetch_papers.py

# 只抓取、看结果，不写文件
python scripts/fetch_papers.py --dry-run

# 自定义参数
python scripts/fetch_papers.py --max-results 300 --lookback-days 7 --top-n 30
```

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--max-results` | 800 | 向 arXiv 请求的最新条目数，自动分页 |
| `--lookback-days` | 7 | 未见过的论文只收录最近 N 个 UTC 自然日的投稿 |
| `--top-n` | 20 | README 榜单展示的篇数 |
| `--dry-run` | 关闭 | 只抓取解析，不落盘 |

想改抓取方向，编辑 `scripts/fetch_papers.py` 顶部的 `SEARCH_QUERY` 即可，例如：

- `cat:cs.CV` — 纯计算机视觉（当前配置）
- `cat:cs.CV OR cat:cs.LG` — 视觉 + 机器学习
- `cat:cs.CV AND (abs:diffusion OR abs:"vision transformer")` — 视觉下的特定主题

## 部署与配置

仓库推送到 GitHub 后无需额外密钥：Actions 使用内置的 `GITHUB_TOKEN` 提交文件，工作流已声明 `contents: write` 权限。若首次运行报 `Permission to ... denied`，到 **Settings → Actions → General → Workflow permissions** 勾选 **Read and write permissions** 后重跑即可（组织仓库可能还需要管理员放行）。

- **改时间**：编辑 `daily.yml` 里的 `cron`（注意是 UTC）。当前 `'23 0 * * *'` = UTC 00:23 = 北京时间 08:23。
- **手动触发**：Actions → Daily CV Papers → `Run workflow`，可临时指定抓取条数。
- **看运行日志**：Actions 页面对应 workflow run，或开启仓库 Watch 接收失败邮件。

几个已知的平台限制：

- GitHub Actions 的定时任务**不保证准点**，高峰时段常延迟几分钟到几十分钟，属正常现象。
- 仓库若连续 60 天无任何活动，GitHub 会自动停用定时工作流（再次 push 或在 Actions 页面重新启用即可恢复）。
- 如果默认分支设置了分支保护且禁止 `GITHUB_TOKEN` 直接 push，需要为该 token 添加例外，或改用 Personal Access Token。
- arXiv 要求 API 调用保持克制，本项目每天只请求 1 次，并在失败时指数退避重试。
